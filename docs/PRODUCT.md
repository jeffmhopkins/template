# Product

What `<PROJECT>` is and what it must never do. Intake writes this doc from the maintainer's
answers ([intake brief](agents/intake.md)). Every part marked ``<from intake>`` is filled
before the first build row starts.

<a id="pitch"></a>
## Pitch
<!-- @section
-->

`<from intake>`: one sentence on what the product is and who it is for.

<a id="users"></a>
## Users and environment
<!-- @section
-->

`<from intake>`: who uses it, on what operating systems and hardware, and in what setting.

<a id="demos"></a>
## Demos
<!-- @section
-->

`<from intake>`: the first demos, one sentence each, such as "a user imports a CSV and sees
a chart".

<a id="closest"></a>
## Closest existing product
<!-- @section
-->

`<from intake>`: the nearest existing product, and what is different here.

<a id="performance"></a>
## Performance bars
<!-- @section
-->

`<from intake>`: the bars that hold from the first milestone (latency, frame rate,
start-up time, memory), each with the hardware it is measured on.

<a id="out-of-scope"></a>
## Out of scope
<!-- @section
-->

`<from intake>`: what the product does not do.

<a id="never"></a>
## Never-rules
<!-- @section
-->

`<from intake>`: what the product must never require or do, such as accounts, a cloud
service, telemetry or a subscription.

<a id="distribution"></a>
## Distribution
<!-- @section
-->

`<from intake>`: how it ships (installer, store, package registry or web host), signing,
and domains.
